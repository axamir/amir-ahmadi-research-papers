# Annex A — implementation-claim ambiguity

This annex records the difference between an implementation-like description and evidence that an implementation exists or behaves as described. It does not treat terminology as a false claim merely because implementation was not disclosed.

| Term/claim | What the interface said | Operational clarification requested | Result | Status |
|---|---|---|---|---|
| `score ≥ 2` | Entries are retrieved with `score ≥ 2`. | Variables, equation, threshold justification, two-entry worked example, implementation/source status. | None supplied in preserved record. | Not Demonstrated |
| `quality_score` | Substantive responses are stored with `quality_score`. | Observable variables and exact rule distinguishing substantive from generic. | No rule preserved. | Not Demonstrated |
| `sector` | The system classifies the sector. | Implemented labels and deterministic unseen-query classifier. | No labels/rule supplied. | Not Demonstrated |
| `tags` | Stored knowledge has tags. | Field semantics and a worked stored/retrieved record. | No worked record preserved. | Not Demonstrated |
| `PhosphorylatedKnowledge` | The system retrieves entries with that name. | YES/NO whether literal running schema; disclose fields if yes. | Answer described “phosphorylated data structure,” without resolving schema status or fields. | Not Demonstrated |
| Cross-session memory | Great Library “connects all conversations and sessions.” | A fresh-session, arbitrary-fact, negative-control retrieval test. | Available record reports VAREL/MIREN did not demonstrate retrieval; full exact exchange is not yet imported. | Partially Supported as a stated claim; Not Demonstrated as a tested capability |

## Evidential consequence

An implementation-like description can be meaningful and still remain unverified. The required upgrade is modest: a redacted schema or field list, a frozen example record, a deterministic scoring/classification procedure, a pre-specified input/output case, or an independently repeatable memory protocol. Any of these could change the classifications above.

## Claim migration protocol

If a term later changes meaning—for example from physical mechanism to internal metric, computational abstraction, or metaphor—the record will preserve: original wording; new wording; date/source; whether the evidentiary requirement changed; and whether the old claim is withdrawn, narrowed, or retained. A changed definition is not misconduct; it changes what must be tested.
